# Task RA-22: Separate validation items from actionable roadmap work

> Status: pending
> Parent: discoverability and consolidation programme
> Model: sonnet
> Fallback: opus
> Depends on: none
> Effort: S
> Touches: `clusters/*/*/README.md` (roadmap sections only), `scripts/roadmap-collect.sh`, `clusters/07-devops/devops-practices/check-roadmap-sync.sh`, `ROADMAP.md`, `CHANGELOG.md`

## Objective
Items that can only be closed by observing real usage ("Test on N real X", "requires real
session", "Document any new gotchas from real usage") move from `## Roadmap` to a new
`## Validation` section in each skill README, and `ROADMAP.md` reports the two counts
separately.

## Background
- About 30 of 49 open roadmap items are validation items. They cannot be worked as
  tasks, only observed, so they inflate the open count and hide actionable work.
- `ROADMAP.md`'s "Open items by cluster" block is generated by
  `scripts/roadmap-collect.sh` and enforced by `check-roadmap-sync.sh` (CI and pre-commit).
  Never hand-edit between the `ROADMAP-COLLECT` markers; change the generator and run `--fix`.
- Merge tasks RA-08 to RA-13 will carry `## Validation` items into merged skills, so this
  runs first.

## Steps
1. Classify each unchecked item under `## Roadmap` in `clusters/*/*/README.md`. It is a
   validation item if it matches (case-insensitive) `test on`, `test across`,
   `test end-to-end`, `requires real`, `from real usage`, or `as they are encountered`.
   Everything else stays in `## Roadmap`. List your classification in the commit body.
2. In each affected README, move validation items (unchanged text) into a
   `## Validation` section placed immediately after `## Roadmap`. Checked items stay where they are.
3. `scripts/roadmap-collect.sh`: also collect `## Validation` unchecked items. Markdown
   output gains, after the per-cluster open items, a `### Validation backlog (observe in real use)`
   subsection grouped the same way. `--json` adds `"kind":"roadmap"|"validation"`.
   Summary line becomes `**Summary:** <A> actionable | <V> validation | <C> completed`.
4. Update `check-roadmap-sync.sh` only if needed for the new output, and the
   `**Open items:**` header line in `ROADMAP.md` if the script writes it.
5. Run `bash clusters/07-devops/devops-practices/check-roadmap-sync.sh . --fix`.
6. Check other consumers of the collect output still work: `grep -rn 'roadmap-collect' --include=*.sh --include=*.ts --include=*.md .` and run each script that calls it.
7. `CHANGELOG.md` → `### Changed`: `- Roadmap validation items ("test on real X") tracked separately from actionable work.`

## Done when
- [ ] `check-roadmap-sync.sh . --check` exits 0.
- [ ] `ROADMAP.md` shows separate actionable and validation counts, and actionable plus validation equals the previous open count (49, unless another task changed it).
- [ ] `bash scripts/roadmap-collect.sh --json | python3 -c "import sys,json;[json.loads(l) for l in sys.stdin]"` succeeds.
- [ ] The `grimoire-roadmap-status` skill's script (if it parses ROADMAP.md) still runs.
